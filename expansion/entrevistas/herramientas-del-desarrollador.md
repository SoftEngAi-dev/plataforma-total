# 🎤 Banco de entrevista — Herramientas del Desarrollador

> 12 preguntas esenciales + guía de respuestas las que ya sabes del curso

## 🔥 Fundamentales (del contenido del curso)

1. **¿Qué hace Ctrl+P en VS Code?**
   - Abrir cualquier archivo del proyecto escribiendo parte de su nombre  _(Quick Open: navegación veloz por archivos — la uso cientos de veces al día.)_

2. **¿Cuál es la ética del proyecto en el editor?**
   - Abrir la CARPETA del proyecto completa  _(El proyecto es la unidad: la búsqueda global, la terminal y la IA contextual dependen de ello.)_

3. **¿Qué comando muestra en qué carpeta estás?**
   - pwd  _(pwd (print working directory).)_

4. **¿Qué hace la tecla TAB en la terminal?**
   - Autocompleta rutas, archivos y comandos  _(TAB es tu superpoder: menos typos, más velocidad.)_

5. **¿Para qué sirve un virtualenv en Python?**
   - Aislar las dependencias de cada proyecto para que no choquen  _(Cada proyecto tiene su propio set de paquetes/versions; nunca chocan.)_

6. **¿Qué hace `pip install -r requirements.txt`?**
   - Instala todas las dependencias registradas del proyecto  _(La forma estándar de reproducir el entorno de un proyecto en cualquier máquina.)_

7. **¿Qué hace git add antes del commit?**
   - Prepara (stage) los cambios que irán en el próximo commit  _(Add prepara; commit guarda el punto en la historia.)_

8. **¿Cómo debe ser un buen mensaje de commit?**
   - Corto y describe QUÉ cambió y por qué  _(Tú futuro (y tu equipo) lo leerán: comunica el cambio.)_

9. **¿Qué hace `git push -u origin main`?**
   - Sube tus commits y enlaza la rama local con la remota para futuros pushes  _(El -u solo hace falta la primera vez; después, `git push` a secas.)_

10. **¿Qué es un Pull Request?**
   - Proponer cambios de una rama para que otros los revisen antes de fusionar  _(PR = cambio propuesto + revisión + discusión + fusión: la base del trabajo en equipo.)_

11. **¿Cómo se lee un traceback?**
   - De abajo hacia arriba: tipo de error y mensaje primero  _(Tipo + mensaje (abajo) te dicen el qué; los frames (arriba) te dicen el dónde.)_

12. **¿Qué debe pasar ANTES de intentar arreglar un bug?**
   - Reproducir el error de forma confiable  _(Sin reproducción confiable solo estás adivinando.)_

# ⚠️ Errores comunes — 2. Formularios e inputs: la web habla contigo

> HTML y CSS — Diseño Web Total · Lección 2 · Aprender de los errores (propios y ajenos)

- ❌ «id» → Frente a «¿Qué atributo hace que el dato de un input llegue al servidor?» lo fácil es confundirse. **Verdad**: name. Sin name, el input no viaja con el formulario.
- ❌ «class» → Frente a «¿Qué atributo hace que el dato de un input llegue al servidor?» lo fácil es confundirse. **Verdad**: name. Sin name, el input no viaja con el formulario.
- ❌ «Porque el HTML5 bugs mucho» → Frente a «¿Por qué validar también en el servidor si el HTML ya valida?» lo fácil es confundirse. **Verdad**: Porque la validación del cliente se puede saltar/falsificar. Toda entrada del cliente es hostil hasta que el servidor la valida.
- ❌ «No hace falta» → Frente a «¿Por qué validar también en el servidor si el HTML ya valida?» lo fácil es confundirse. **Verdad**: Porque la validación del cliente se puede saltar/falsificar. Toda entrada del cliente es hostil hasta que el servidor la valida.

## 🩹 Antídoto universal
1. Lee el mensaje de error COMPLETO antes de googlear.
2. Pon el error exacto a la IA local y pide explicación, no solución.
3. Documenta el error en tu bitácora: error → causa → fix.

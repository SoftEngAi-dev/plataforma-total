> Git y GitHub — Tu Historia Nunca Se Pierde · Lección 4 · Aprender de los errores (propios y ajenos)

- ❌ «push directo a main» → Frente a «¿Cuál es el ciclo correcto de contribución?» lo fácil es confundirse. **Verdad**: rama → commits → push → PR → revisión → merge. El PR con revisión es el corazón del trabajo en equipo moderno.
- ❌ «fork del compañero» → Frente a «¿Cuál es el ciclo correcto de contribución?» lo fácil es confundirse. **Verdad**: rama → commits → push → PR → revisión → merge. El PR con revisión es el corazón del trabajo en equipo moderno.
- ❌ «Siempre» → Frente a «¿Cuándo necesitas hacer fork?» lo fácil es confundirse. **Verdad**: Cuando el repo no es tuyo/no tienes permiso de push (open source). Fork = tu copia en tu cuenta, que permite proponer PR al original.

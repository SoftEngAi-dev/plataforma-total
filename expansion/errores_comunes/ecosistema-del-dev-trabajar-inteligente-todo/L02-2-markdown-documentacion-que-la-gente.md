# ⚠️ Errores comunes — 2. Markdown + documentación que La gente lee

> Ecosistema del Dev — Trabajar Inteligente Todos los Días · Lección 2 · Aprender de los errores (propios y ajenos)

- ❌ «Todo el código» → Frente a «¿Qué debe comentar un buen comentario en código?» lo fácil es confundirse. **Verdad**: El POR QUÉ/contexto no obvio del código (el QUÉ lo dice el código mismo). Razones, advertencias y decisiones: lo que futuras lecturas no pueden inferir.
- ❌ «El autor» → Frente a «¿Qué debe comentar un buen comentario en código?» lo fácil es confundirse. **Verdad**: El POR QUÉ/contexto no obvio del código (el QUÉ lo dice el código mismo). Razones, advertencias y decisiones: lo que futuras lecturas no pueden inferir.
- ❌ «Legal» → Frente a «¿Cuál es la estructura de un README que convierte?» lo fácil es confundirse. **Verdad**: Qué hace + demo + install 3 pasos + ejemplo de uso (el lector decide en <1 minuto). La claridad al abrir = usuarios/contribuidores que se quedan.
- ❌ «Solo título» → Frente a «¿Cuál es la estructura de un README que convierte?» lo fácil es confundirse. **Verdad**: Qué hace + demo + install 3 pasos + ejemplo de uso (el lector decide en <1 minuto). La claridad al abrir = usuarios/contribuidores que se quedan.

## 🩹 Antídoto universal
1. Lee el mensaje de error COMPLETO antes de googlear.
2. Pon el error exacto a la IA local y pide explicación, no solución.
3. Documenta el error en tu bitácora: error → causa → fix.

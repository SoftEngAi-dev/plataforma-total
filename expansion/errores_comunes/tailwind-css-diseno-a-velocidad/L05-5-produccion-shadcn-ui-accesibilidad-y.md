# ⚠️ Errores comunes — 5. Producción: shadcn/ui, accesibilidad y buenas prácticas

> 🎨 Tailwind CSS — Diseño a Velocidad · Lección 5 · Aprender de los errores (propios y ajenos)

- ❌ «Un framework de CSS rival» → Frente a «¿Qué es shadcn/ui?» lo fácil es confundirse. **Verdad**: Componentes accesibles (Radix + Tailwind) que copias a tu proyecto y son tuyos. No es una dependencia: copia el código del componente a tu repo, con accesibilidad Radix y estilos Tailwind incluidos.
- ❌ «Un plugin de jQuery» → Frente a «¿Qué es shadcn/ui?» lo fácil es confundirse. **Verdad**: Componentes accesibles (Radix + Tailwind) que copias a tu proyecto y son tuyos. No es una dependencia: copia el código del componente a tu repo, con accesibilidad Radix y estilos Tailwind incluidos.
- ❌ «hidden» → Frente a «¿Qué clase de Tailwind muestra un texto solo a lectores de pantalla?» lo fácil es confundirse. **Verdad**: sr-only. sr-only lo oculta visualmente pero mantiene accesibilidad para tecnologías asistivas.
- ❌ «invisible» → Frente a «¿Qué clase de Tailwind muestra un texto solo a lectores de pantalla?» lo fácil es confundirse. **Verdad**: sr-only. sr-only lo oculta visualmente pero mantiene accesibilidad para tecnologías asistivas.

## 📖 Contenido

```text
PROYECTOS: DONDE OCURRE LA MAGIA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Las lecciones te dan vocabulario. Los proyectos te dan JUICIO.

LA FÓRMULA
1 lección nueva + experimentar 10 min = aprendizaje
1 proyecto pequeño terminado = conocimiento que se queda

TIPOS DE PROYECTO (escala)
• Mini (30-60 min): una idea, un archivo, hoy mismo
• Semana: algo con 2-3 conceptos juntos (Python + archivos + JSON)
• Mes: una app que enseñes con orgullo (incluye README)

CÓMO NO FRACASAR EN PROYECTOS
1. Escópalo TAN pequeño que no pueda fallar (¿"app de tareas"? empieza: "guardar UNA tarea en un archivo")
2. Termina antes de mejorar: versión fea funcionando > bonita sin funcionar
3. README siempre — explicar tu código es la mitad del aprendizaje

🚀 La pestaña Proyectos te crea esqueletos listos para arrancar.
```

## 📝 Quiz de la lección

### 1. ¿Cuál es el error más común al empezar un proyecto?
- A) Usar un lenguaje nuevo
- B) Ámbito demasiado grande desde el inicio
- C) Escribir un README
- D) Terminar antes de mejorar
### 2. ¿Por qué escribir un README en cada proyecto?
- A) Para que GitHub lo muestre bonito
- B) Porque explicar tu código consolida el aprendizaje y es evidencia de tu trabajo
- C) Es requisito del sistema
- D) Para ganar puntos

---

## 🔑 Respuestas y explicaciones

**1.** ✅ Ámbito demasiado grande desde el inicio — Haz el ámbito tan pequeño que no pueda fallar; luego creces.
**2.** ✅ Porque explicar tu código consolida el aprendizaje y es evidencia de tu trabajo — Documentar = enseñar = consolidar. Y tu portafolio lo agradece.
